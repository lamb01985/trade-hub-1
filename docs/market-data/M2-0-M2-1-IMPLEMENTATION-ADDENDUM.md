# First-increment contracts: M2.0 and M2.1

Status: independently reviewed; user approved bounded M2.0/M2.1 implementation on October 25, 2026. Activation, deployment and production configuration remain unapproved. This addendum is normative for the first two phases of the [Milestone 2 specification](./MILESTONE-2-LIVE-MARKET-DATA-SPEC.md). Later options persistence, index/futures enablement and hosting remain separate gated specifications. No dependency is installed by this document.

## 1. Scope and stable intermediate behavior

M2.0 exposes capability evidence without changing signal/analytics logic. M2.1 introduces unified **read-only three-ETF context**. Live Market Map analytics follow in M2.2. Existing trading tools can remain in an explicit Legacy mode, but in Unified context mode the App must not mount the legacy coach, setup evaluator, wheel hydration or scanner subscriptions. Those tools show “Migration pending: current action evaluation unavailable” until their named M2.2/M2.3 adapters are reviewed. Preserving their files/storage is not permission to keep timestamp-poor actionable consumers running behind the new view.

M2.1 owns `App.jsx`, `useLiveData.js`, `useLiveDataMulti.js`, `useBot.js`, `conditionEvaluators.js` and `setupEngine.js` boundary guards. The latter three reject or remain unmounted for Unified mode until passed a supported envelope; no existing setup rule is changed. `Command`, `Levels` and `Chart` consume only quote/bar evidence in that mode. M2.2 migrates Market Map and sectors; M2.3 migrates IV/Wheel options. Unsupported symbols show a typed unavailable state, never the previous selected ETF. Historical review remains a different mode.

## 2. Exact first-phase resources

Vercel routes and Python resource suffixes use the same names. Public path is `/api/market/{resource}`; internal path is `/api/v1/market-data/{resource}`. GET only; unknown resource 404; unsupported method 405; unknown/duplicate query keys and invalid values 400. No raw upstream URL/path input.

| Resource | Accepted query | Response data |
| --- | --- | --- |
| capabilities | none | records array of capability rows for the configured profile |
| snapshot | symbol exactly QQQ, SPY or IWM | quote observation containing separate nullable last_trade, bid and ask observations; no last-price fallback invented from bars |
| bars | symbol as above; interval exactly 1m; from/to real YYYY-MM-DD, from<=to; adjusted true/false default true | chronological RTH bar array with explicit start/end, completed and adjustment metadata; at most 10 exchange sessions of minute data |

`options` and `intelligence` resources initially return 503 FEATURE_NOT_ENABLED without upstream access. VIX/NQ/ES capabilities may show denied/unverified evidence but have no enabled price endpoint in M2.1. Unrecognized instruments are 400 UNSUPPORTED_INSTRUMENT, not a guessed provider ticker.

Every response has `schema_version=market-data-envelope-v1`, request_id, deployment_profile, generated_at UTC, availability, nullable data, quality, and nullable error. Required `quality` fields: freshness enum from the parent spec; coverage enum; policy_version; nullable source_age_seconds; missing_fields string array; reasons string array. Required error shape when non-null: `{code: string, retryable: boolean, retry_after_seconds: integer|null}`. No raw provider exception/message/URL. Successful capabilities data is `{records: Capability[]}`; quote/bar data uses the field contracts below. Errors never omit request/profile/quality metadata; canonical instrument is nullable only before valid input resolution.

Common data identity fields: canonical_instrument_id=`ETF:US:{symbol}`, provider_symbol=symbol, asset_class=ETF, currency=USD, provider=Massive, endpoint_family, transport=REST, session_id/date, feed_timeframe, declared_delay_seconds nullable, ingested_at, retrieved_at and policy_version. UTC timestamps are timezone-aware ISO 8601; raw provider times are decimal strings. Each quote field object has value, price_kind, source_time, raw_time, timestamp_unit, feed_timeframe and field_quality; absent observations are null, never zero. A quote pair adds bid_size/ask_size nullable and both sides' source identity. Each bar has start, end, completed, open/high/low/close, volume nullable, adjustment flag, source identity and interval. Nonfinite JSON numbers and booleans masquerading as numbers are invalid.

Capability rows require profile, asset_class, endpoint_family, instrument_scope, field_group, recency_class, state, evidence_source, checked_at, expires_at, observed_fields and known_quota nullable. Evidence_source values USER_REPORTED, PUBLIC_DOCUMENTATION, CONNECTOR_OBSERVED, DEPLOYMENT_PROBED are never interchangeable. Capability envelopes are metadata and use freshness UNKNOWN, coverage COMPLETE for a complete registry enumeration; this does not mean their quoted data is fresh.

Status rules: valid data 200, including explicitly partial/empty coverage; bad input 400; app/service authentication 401/403; explicit provider entitlement denial 403 with error code PROVIDER_NOT_ENTITLED; budget exhaustion 429; malformed/upstream failure 502; unconfigured/disabled dependency 503; elapsed refresh deadline 504. The client distinguishes errors by code, not status alone, so provider 403 cannot sign out the operator. Valid empty selection gets data array empty and coverage COMPLETE only if the instrument/window was verified; otherwise coverage UNKNOWN and availability UNAVAILABLE.

## 3. Service authentication and local routing

Configuration names: `MARKET_DATA_SERVICE_URL`, `MARKET_DATA_SERVICE_TOKEN`, `MARKET_DATA_DEPLOYMENT_PROFILE`, `MASSIVE_ACCOUNT_BUDGET_SCOPE`, `MASSIVE_REQUESTS_PER_MINUTE`, `MARKET_DATA_UNIFIED_ENABLED`. Python additionally owns `MASSIVE_API_KEY` and existing private database settings. No VITE_ secret variable is permitted. The service token must be independently generated with at least 32 random bytes; no value is created or set during planning.

Gateway sends Authorization Bearer with the configured opaque token and `X-TradeHub-Audience: market-data-v1`. Python verifies the bearer value with constant-time comparison and requires that exact audience header before provider/cache access. The audience header alone has no authority. No forwarding of browser Authorization, cookies, arbitrary headers or destination URLs. HTTPS required hosted; literal loopback HTTP permitted only in development for both ends. A malformed/missing URL/token/profile fails startup/readiness; operator login failure remains separate. Service diagnostic output exposes presence/profile only, never token/account identifiers.

Add the named configuration keys to the server-only allowlist in `scripts/vite-api.mjs`, and exact resource routing for capabilities/snapshot/bars/options/intelligence to `api/market/[resource].js`; do not introduce a filesystem wildcard. Historical preview rejects those live routes with its existing intentional-disable 503/header. Native Vercel owns deployed routing. Test unknown resources, direct .js requests, service-token non-forwarding, wrong service audience, missing configuration and identical local/native-handler JSON contracts.

## 4. ETF sessions and freshness precedence

Propose [exchange_calendars 4.13.2](https://pypi.org/project/exchange_calendars/4.13.2/) as the pinned first-phase calendar dependency, using XNYS regular-session schedules for the shared US ETF RTH context. Review its supported date range and compare the release's supported-year holiday/early-close fixtures with published exchange schedules before activation. Pin transitive dependencies in the future lock/requirements change. No library or download has been installed now.

First-phase CURRENT context is RTH only: scheduled open inclusive, scheduled close exclusive. Extended-hours observations may be displayed as extended context but get freshness UNKNOWN with EXTENDED_CONTEXT_ONLY, never the RTH current gate. Outside RTH, LAST_CLOSED_SESSION requires an observation associated with the latest completed scheduled session. Unknown dates/calendar version coverage produce SCHEDULE_UNKNOWN and UNKNOWN freshness. Futures/options/index session policies are not inferred from this ETF calendar and must be specified before their enabled phase.

Precedence: invalid identity/value/time units -> reject data; time >now+5s -> INVALID_CLOCK; time in (now,now+5s] -> UNKNOWN/CLOCK_SKEW with original negative age and no current gate; absent time -> UNKNOWN; explicit delayed/EOD/unknown feed -> corresponding DELAYED or UNKNOWN, never CURRENT; scheduled RTH with verified real-time profile and age<=30s -> CURRENT; older RTH observation -> STALE; closure -> LAST_CLOSED_SESSION only if matching latest completed session, otherwise STALE. Delayed source beyond declared delay+60s becomes STALE. Preserve calculated negative age for diagnostics; no clamp to zero.

For 1m bars, provider t is start and end=start+60s; completed only when end<=analysis clock. Newest required end age<=90s. Test exact opens/closes, holidays, early closes, leap days, DST transitions, year boundaries, unsupported dates, extended hours, -1/-5/-6 second ages and each positive-age boundary.

## 5. Exact timestamp ownership and legacy analytics isolation

| Endpoint/field | Raw unit and meaning | New-layer handling |
| --- | --- | --- |
| stock snapshot lastTrade.t, lastQuote.t, updated | nanoseconds; trade/quote event versus snapshot update | preserve independently; updated cannot refresh an older quote/trade |
| stock snapshot min.t; stock/options aggregate results[].t | milliseconds; aggregate window start | derive end only from known interval; never use start as trade/quote event time |
| option snapshot last_quote.last_updated, last_trade.sip_timestamp, underlying_asset.last_updated | nanoseconds; separate quote/trade/underlying observations | separate times and feed timeframes; no newest-chain reference replacing absolute age |
| option historical quotes/trades sip_timestamp | nanoseconds; individual market event | preserve event identity/units; no inference of full-chain flow |
| index snapshot last_updated | nanoseconds; provider index observation | index adapter only, after entitlement/session approval |
| futures trade/quote timestamp, aggregate window_start | nanoseconds; event/window start | product adapter owns interval/end/session_end_date semantics |
| provider ISO schedule/session_end_date fields | timezone-aware UTC schedule or exchange session date | do not numerically divide or infer calendar date from receipt time |

Missing/invalid units yield UNKNOWN/rejection; no magnitude heuristic in the new path. Validate endpoint documentation against one server-profile sample during phase activation and record the mapping policy version. Existing heuristic routines remain historical-only and cannot re-interpret new normalized time values.

Add new `app/market_data/live_options_adapter.py` in M2.3. It may reuse arithmetic outputs from `market_intelligence.options_report`, `positioning` and `gamma_scenarios`, but must discard/replace old `pagination_complete`, liquidity pass/failure, quote_stale, relative quote ages and source-reference quality fields. New envelope quality is the only live authority. Do not serialize the old quality fields under a live label. Old report-builder behavior remains unchanged. Tests must feed a partial chain and stale/future quotes into reused calculations and assert they cannot become complete/current. This adapter is a named future file and a prerequisite to enabling options, not a change made now.

Field validation is specific: retain observed zero OI/volume/sizes and a zero option bid as evidence. A zero bid cannot satisfy a two-sided usable-quote gate or expected-move calculation. Ask must be positive, bid nonnegative, ask>=bid; observed stock trade/index/futures prices used by the first ETF context must be strictly positive finite values. Midpoint never becomes a trade.

## 6. Shared budget and coexistence

One budget scope represents the actual Massive account, not each API key/profile/tab. Before enabling Unified mode, inventory every known producer: TradeHub legacy REST, new gateway, Python analysis/options routes and hosted scanner. All their **provider HTTP attempts** must share an atomic account budget and concurrency admission, including retries, pages and reference discovery. Implement admission at Python `MassiveMarketDataProvider._get_payload` and TradeHub `polygonFetch` transport boundaries, preserving legacy returned data and frozen strategy rules. New bounded adapter methods opt into the new deadlines; existing callers retain their data semantics but can receive explicit temporary rate/dependency errors. Do not silently change them into empty data.

Use one parent Redis account bucket and concurrency pool across every integrated environment sharing the actual Massive account. Local/staging/production allocations must reserve through this same parent; environment prefixes isolate data/auth records, never multiply provider quotas. Independently verified separate accounts may have separate parents. Local multi-process verification uses a shared test store rather than independent memory quotas. Configured account scope is a non-secret label, never a key hash. Redis-time rolling 60-second admission limits total attempts to configured N (default five if unverified); count each attempted HTTP request once, no refunds. Atomic leases limit concurrent requests to four, expire after the enforced attempt deadline plus five seconds, and release on completion. Backend unavailability fails closed. The isolated service process owns request coalescing; multiple service owners remain disallowed until shared coalescing/leases are tested.

Reserve capacity explicitly: R legacy/background attempts/minute, verified from measured activity; new requests may use at most N-R, while the combined rolling budget still never exceeds N. If N/R cannot support the proposed cadence, show limited refresh and block current claims. Unknown other-account usage is a documented limit: this design controls integrated TradeHub/engine traffic, not external applications holding the same account's keys. WebSocket channel/connection limits are separate from REST request counts; existing direct browser keys also remain outside enforceable REST quotas and are a residual risk until retired.

Admission priority: active ETF quote, required current minute-bar gaps, selected options, historical/reference/background. FIFO within each class. No higher-priority claim can exceed the combined account budget; lower-priority work may remain deferred with an explicit reason. Every page/retry re-enters admission. If Retry-After or queue wait reaches the remaining refresh deadline, stop and publish the failed/partial attempt; do not sleep then restart another overlapping refresh.

Add bounded provider methods returning `{items, pages_read, pagination_complete, next_cursor_present, requested_window, returned_window, error}`. They use a 10-second attempt timeout within 30 seconds overall, maximum 10 pages, same-origin/path cursor validation and chronological/identity checks. A queue wait counts against the deadline. Do not replace the existing `_get_paginated_payload` globally: its 10,000-page/20-second legacy behavior is not the new API contract and must not leak into new calls.

## 7. Phase-specific file list and proof

M2.0/M2.1 creates TradeHub `api/market/[resource].js`, `api/_lib/marketDataGateway.js`, `contracts/market-data-envelope-v1.schema.json`, `src/lib/marketDataContract.js`, `src/hooks/useMarketData.js`, and the three market-data test modules named in the parent specification. Modify local middleware/configuration docs, App and the boundary consumers listed in section 1; modify `api/_lib/polygon.js` for shared admission. Keep historical report schemas unchanged.

Python creates `app/market_data/{capabilities,instruments,quality,sessions,budget,service,api}.py`; modifies `base.py`, `massive.py`, `main.py`, `config.py`, `requirements.txt` and corresponding test modules. The new sessions/quality modules own first-phase rules; do not replace `app/freshness.py` defaults used by frozen decisions. Redis budget transport uses existing httpx, with protected configuration names and mocked test transport; no new database migration is needed for in-memory first-phase observations/capability evidence. Durable evidence retention waits for M2.3 rights/storage approval. `live_intelligence.py`, the live options adapter and `live-intelligence-v1` schema belong to later named phases.

Acceptance tests prove all producers reserve before fetch, 100 simultaneous admissions cannot exceed N or four leases, pagination/retries count, store failure performs no upstream request, queued deadlines produce no late fetch, and denial in one product leaves other capabilities intact. M2.1's new-mode gates are tested before real source activation. Existing TradeHub and engine suites must pass; no live provider call is a unit test.

The simultaneous-admission test must mix local, staging and production workloads sharing one account parent and prove their combined count/leases stay bounded. No credential or authentication-state sharing between those environments is implied.

Sustained-session measurement is a release gate after deployment-profile rights/quota confirmation: sample every ten server-clock seconds over a full scheduled RTH session, for each ETF separately. Denominator includes every sample including missing data, startup, refresh failures and provider outages; only exchange-declared halted windows are separately counted and excluded with evidence. A sample passes only when the required quote fields are CURRENT with matching identity and quality. Report all three per-symbol percentages plus their minimum; require each >=99%, otherwise mark the beta nonconforming and investigate without loosening age thresholds. Bar coverage and options quality have separate measures and cannot be averaged into a good stock quote percentage. A Sunday/offline run does not satisfy this gate.

## Approval meaning

Approval can authorize a bounded first-phase implementation only after the exact account/usage profile and dependency changes are accepted. It does not approve new subscription spending, production configuration, later storage migrations or deployment. If those account facts remain unresolved, offline contract work may be separately approved, but no live entitlement or production readiness claim is allowed.

## 8. Final-review refinements: admission protocol

The following refines section 6 and is normative for both Node/Python wrappers. Create `api/_lib/marketDataBudget.js` and Python `app/market_data/budget.py` with the same tested contract: `admit(account_scope, attempt_id, role, timeout_ms)` returns `{granted,lease_id,retry_after_seconds,reason}`; `release(account_scope,lease_id)` releases concurrency only. These are server-internal functions, not unauthenticated HTTP routes. Use the existing server Redis credentials through provider-specific REST clients; Python may use existing httpx for Redis REST. No provider fetch is permitted without a grant.

Policy uses MASSIVE_REQUESTS_PER_MINUTE=N and required MASSIVE_LEGACY_RESERVED_REQUESTS_PER_MINUTE=R, with 0<=R<N. Unified readiness fails if R is unspecified or invalid; unknown N defaults five and cannot establish a live-cadence claim. A protected shared policy record fixes N/R/policy_version for an account parent; caller mismatch fails closed rather than silently creating another bucket. Changing it is an explicitly approved configuration action, not part of this draft. Parent keys are `md:{account_scope}:policy`, `:attempts`, `:new_attempts`, `:leases`; no deployment prefix on these keys.

One atomic Redis Lua operation uses Redis TIME, removes attempts at/before now-60000ms and leases at/before now, then checks total attempts<N, active leases<4, and—for role=new—new_attempts<N-R. role=legacy may use remaining parent capacity; R is protected room from new traffic, not an independent extra budget. On grant, add the UUID attempt ID to the total sorted set, to new_attempts only for role=new, and to leases with expiry now+timeout_ms+5000. Record the same UUID as lease_id. Reusing an attempt ID is rejected; the wrapper must not issue a second fetch. On denial, perform no reservation and return a retry hint until the earliest blocking reservation expiry (minimum one second). Accepted timeout is 10000ms for new work, 20000ms for legacy work; a later retry/page always gets a fresh attempt ID. Release removes only the matching lease; consumed attempts age out naturally. Redis failures grant nothing. Lease expiry is recovery from a crashed request, not permission to let an upstream request run beyond its timeout.

Priority/FIFO applies only to the single new-service scheduler's queue, not to globally ordered legacy requests. Legacy callers reserve immediately or receive an explicit temporary limit/dependency error; they do not join a fictitious cross-runtime FIFO. New queue waits and retries count against the refresh deadline; if the retry hint exceeds time remaining, abort that refresh attempt. The shared parent remains authoritative across every queue/process/environment. Tests use the same Lua input/result fixtures across Node/Python, include repeated IDs, policy mismatches, expired leases and release-without-refund, and test the actual Redis atomic path in a local/shared test store before release. Existing fixed-window `access.reserve` is not reused for this rolling algorithm.

## 9. Final-review refinements: exact first-phase wire and daily deferral

All new schemas reject additional properties except explicitly versioned provider-detail maps. The envelope's canonical identity is **only** top-level `instrument` (nullable before valid selection, and null for capabilities). Instrument object fields are required: `canonical_id` string, `provider_symbol` string, `asset_class` ETF for M2.1, `currency` USD. Top-level required fields are schema_version, request_id, deployment_profile, generated_at, instrument, source, availability, data, quality, coverage_details, error. Missing profile configuration uses the reserved public label UNCONFIGURED. `source` has provider=Massive, transport=REST, endpoint_family string. Non-data errors have data=null; no source field is manufactured as an observation time.

`field_quality` is exactly `{valid: boolean, freshness: FreshnessEnum, reasons: string[]}`. Every observation carries `instrument_id` equal to top-level instrument.canonical_id, endpoint_family, value (finite number), price_kind, source_time nullable UTC string, raw_time nullable decimal string, timestamp_unit in NS/MS/ISO/UNKNOWN, feed_timeframe in REAL_TIME/DELAYED/EOD/UNKNOWN and field_quality. Price_kind adds explicit BID and ASK for side observations. These do not become TRADE values. Snapshot data is exactly `{last_trade: Observation|null,bid: Observation|null,ask: Observation|null,bid_size: integer|null,ask_size: integer|null}`; sizes must be nonnegative. Each observation's own quality remains visible even when the aggregate differs.

Quality required fields are freshness, coverage, policy_version, source_age_seconds nullable number, missing_fields string[], invalid_fields string[], reasons string[]. `coverage_details` is exactly `{requested_window: Window|null,returned_window: Window|null,pages_read: nonnegative integer,pagination_complete: boolean|null,observations: nonnegative integer,minimum_required: nonnegative integer|null,missing_intervals: UTC-string[]}`. Window fields: from/to ISO UTC strings, interval string, adjusted boolean|null. For snapshots/capabilities windows and minimum_required are null; snapshot pagination is true with pages_read=1 only after a successful single-snapshot read, and capabilities is an enumeration rather than a provider-time series. Error/unknown coverage uses null completion, not true.

A stock snapshot's aggregate CURRENT predicate requires **both bid and ask** to be valid, positive, bid<=ask, same instrument/session, each CURRENT under section 4, with absolute side-time skew<=5s and verified non-delayed profile. A stale/missing last trade does not invalidate a fresh quote pair but cannot be displayed as a current trade. source_age_seconds for the aggregate is the older side's age. If either required side is missing/invalid, aggregate freshness UNKNOWN with MISSING_REQUIRED_QUOTE/INVALID_QUOTE and coverage PARTIAL; if a required side is stale/delayed, that status blocks CURRENT. Both sides must match last-closed session for LAST_CLOSED_SESSION. The 99% gate measures this exact pair predicate; it is not satisfied by a fresh last trade alone. No bid/ask entitlement means a truthful unavailable/partial quote context, not an upgrade inferred from the plan label.

Bar data is `{interval: 1m,adjusted: boolean,bars: Bar[]}`. Each bar has required instrument_id, start/end UTC, completed boolean, open/high/low/close finite positive numbers, volume nonnegative number|null and source_time/raw_time/timestamp_unit from section 5. Filter first-phase history to scheduled RTH; preserve missing intervals rather than inserting zero bars. Aggregate bar freshness uses the newest required completed end, only after full requested-window/identity checks. Capability data is exactly `{records: Capability[]}` with fields in section 2 and no instrument identity wrapper inside data. Error object/status rules remain section 2; JSON null is used for absent values, never omitted required fields.

Daily interval=1d is **deferred to M2.2** and rejected as UNSUPPORTED_INTERVAL in M2.1. Its implementation specification must distinguish provider daily aggregation boundaries from RTH session boundaries, document adjustment/extended-hours inclusion, reject unfinished current-day structure, and verify early-close/DST cases before daily fields are enabled. This avoids pretending that the minute-bar end formula defines a daily session.
