# Provider credential confinement and protected-preview preparation

Status: design for independent EGM review. User authorizes implementation after review; no deployment, credential rotation, production changes or live-service activation.

## Problem and goals

The completed security and M2 implementation reports identify one remaining deliberate key disclosure: GET /api/polygon/ws-auth returns the long-lived Massive key to signed-in browsers. Remove that delivery completely while preserving authenticated price and quote access, existing legacy tools and the separate read-only Unified ETF view. Prepare a small isolated release without importing unrelated research/strategy changes.

## Chosen architecture

Use the existing authenticated server REST proxy as the credential-holding transport, not a new persistent WebSocket service. Replace the browser MassiveStream implementation with a shared polling compatibility adapter. Keep MassiveStream/MassiveStreamClient callbacks and per-ticker subscription reference counts. Only same-origin /api/polygon/proxy is requested; no provider WebSocket, auth frame or provider credential exists in browser state. The old ws-auth route remains as an authenticated 410 STREAMING_CREDENTIAL_DELIVERY_RETIRED tombstone, private/no-store, performing no provider fetch, key read or quota reservation. Anonymous/expired sessions still fail authentication first.

One poll worker per browser module services distinct subscribed tickers serially, no overlapping cycles. Schedule the next cycle no sooner than ten seconds after the previous cycle completes; each ticker gets at most one snapshot attempt and one entitlement-only last-trade fallback per cycle, with no adapter-level retries. Preserve FIFO ticker order within the cycle. Honor numeric Retry-After up to one day; a larger/invalid hint stops automatic refresh with an explicit error instead of retrying early. Network failures wait at least ten seconds, increasing to sixty seconds after repeated failures. Quota exhaustion remains explicit and cannot become an empty successful response. Large ticker sets have visibly reduced refresh cadence, never promised ten-second delivery for every ticker. A cycle obtains one fresh snapshot per distinct ticker through the existing proxy; it bypasses the old snapshot cache and emits only validated trade/quote observations matching the exact requested ticker. Positive finite trade prices and nonnegative sizes; bid/ask positive finite and bid<=ask. Explicit snapshot NS event times convert to legacy millisecond callbacks; malformed/missing times suppress the affected callback, and receipt time never substitutes for source time. M2's exact normalization/quality authority remains Python. Optional last-trade REST fallback is used only when snapshot access is denied, not after arbitrary failures. Denial is scoped to snapshot family, never operator login. Fallback quote remains unavailable. Backoff/Retry-After is bounded and generation/session cancellation prevents late events, retry, new requests or reconnect after logout/unsubscribe. Full fetch plus body parsing has an absolute 15-second timeout. Snapshot/last-trade attempts and retries pass the existing server helper/budget. Add independent MASSIVE_BUDGET_ENFORCED=true admission control on both Node and Python transports, ORed with the existing Unified flag; preview requires it true. Disabling Unified consumers never disables account admission. Rollback retains this flag and the protected account policy. No client-side retry storm or overlapping hydration.

Transport callbacks denote REST transport readiness, never CURRENT or real-time recency. Hooks expose transport=REST_POLL; labels say authenticated REST polling / source recency unverified. Remove WebSocket-connected/real-time labels. Existing legacy fallback poll loops must not double-poll while the compatibility adapter owns observations; old context/history requests remain unchanged. Starting without subscriptions must not deadlock hooks that subscribe in onConnected: connect emits readiness asynchronously, then subscribe starts work. Add a per-ticker onStatus callback with trade_available, quote_available, reason and transport fields. Hooks clear the corresponding retained price/bid/ask when fields disappear, fail validation, are denied or time out; do not silently retain yesterday’s quote. Errors retain explicit unavailable state and no invented price. Last subscriber disconnect cancels timer/controller and clears observations. New Unified mode still unmounts legacy consumers and uses only M2 envelopes.

## Alternatives and tradeoffs

A Python WebSocket relay would preserve lower latency, but adds persistent hosting, cross-origin browser authorization, connection/channel budgets, reconnect/backfill and new deployment dependencies. Vercel functions are not assumed to host a persistent WebSocket server. Existing authenticated REST is the smaller release. Polling loses tick-by-tick delivery and can consume more REST quota; explicit labels and shared budgets must make this limitation visible. It cannot satisfy the 99% quote-pair gate on an insufficient subscription. Previously copied keys remain valid until a separately approved rotation; deleting the endpoint cannot revoke them.

## Exact review refinements

Polling: one failed cycle waits10seconds, two consecutive failed cycles20seconds, three or more60seconds. Any cycle with every requested ticker successfully parsed resets the consecutive-failure counter. The whole worker waits the maximum Retry-After observed across tickers or the failure delay, whichever is larger. Do not immediately retry a failed ticker within its cycle. A response header X-TradeHub-Auth-Required=true terminates and dispatches operator expiry before body parsing; only a403 without this header permits one last-trade fallback. Other401 responses stop with authentication unavailable, never fallback. Provider403 cache remains family-scoped.

Status signature: onStatus({ticker,trade_available:boolean,quote_available:boolean,reason,transport:'REST_POLL'}). Reasons: WAITING,AVAILABLE,PARTIAL,NOT_ENTITLED,INVALID_DATA,UPSTREAM_UNAVAILABLE,RATE_LIMITED,SESSION_ENDED. Initial WAITING and all-error statuses make both fields false. Emit status before any valid trade/quote callbacks; PARTIAL independently clears only missing fields. Missing/invalid optional sizes become null, not zero; they do not suppress valid prices. Snapshot lastTrade.t/lastQuote.t are explicitly NS and mapped to legacy millisecond timestamps; fallback /v2/last/trade/{ticker} results.t is NS and authoritative identity is results.T (not a guessed top-level symbol). Preserve source time, never stamp receipt. Each ticker has its own incrementing subscription generation. Unsubscribe aborts that ticker’s in-flight request and immediately continues remaining tickers; a resubscribe cannot consume an old response. Last disconnect aborts the whole adapter and all scheduled work.

MASSIVE_BUDGET_ENFORCED accepts exactly true, defaults false for existing installations, and ORs with MARKET_DATA_UNIFIED_ENABLED exactly true at both transport boundaries. Protected-preview preflight requires independent enforcement true. Enabled admission with missing/invalid policy/store fails closed before fetch; disabling Unified during rollback cannot bypass it. Add this server-only variable to local loader and Python settings.

Preview preparation artifacts: docs/preview/{PROTECTED-PREVIEW-RUNBOOK,CONFIGURATION-AUDIT,ISOLATION-MANIFEST}.md; config/vercel.preview.json (alternate local config, never overwrite vercel.json); scripts/preview-preflight.mjs reads process environment only and prints check names/booleans/errors; scripts/verify-protected-preview.mjs is not executed against a live target here and accepts HTTPS PREVIEW_URL, private cookie/header values only from environment, verifies anonymous denial, authenticated ETF identity/schema/profile, ws-auth410/no key, service403 versus operator expiry and explicit freshness. No credentials in command arguments/query/logs. A Python preview-only launch module runs only the dedicated market router, one worker, no legacy analysis/background scanners/brokers/notifications, with a module-owned scoped service lifecycle; no deployment/app activation here. This avoids importing unrelated legacy main.py/strategy changes into the service release.

The approved read-only entitlement probe script defaults to configuration-only inspection and requires an explicit --allow-provider-reads flag, verified deployment-account attestation, valid account-budget configuration and bounded maximum eight HTTP attempts before any provider request. Snapshot QQQ/SPY/IWM, one historical minute-bar sample each and two bounded QQQ options probes (contracts/chain) establish only observed access, not plan-wide rights. Probe uses provider transport admission, records sanitized status/field-presence/source-age and never raw data, URLs, credentials or key hashes. No provider calls will be executed from the unproven local key in this task. Missing service values and lack of a linked Vercel project are reported, not invented. Current local inspection found only a Python MASSIVE_API_KEY and cannot prove deployment equivalence.

The verifier reports this as nonconforming rather than silently passing.
