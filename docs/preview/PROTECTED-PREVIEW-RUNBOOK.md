## Rollback

If credentials appear in a response, isolation/auth fails, or source quality is wrong, stop the preview and preserve sanitized evidence. Disable Unified consumption for that preview and stop its dedicated Python process/container. Revoke preview access/sessions through the dedicated store as separately authorized. Keep MASSIVE_BUDGET_ENFORCED=true and the shared parent/policy intact; never flush/refund account attempts or share production auth state. Preview-only mode must show inactive/unavailable, not mount legacy consumers.

Restore only a reviewed security-hardened credential-confined artifact. There was no prior deployed confined preview in this task, so the default rollback is preview OFF, not an older production build that returns keys. Never restore ws-auth key delivery, delete journals, alter existing user databases or rotate secrets automatically. Previously copied provider keys remain valid until a separately approved provider-side revocation/rotation; removing the endpoint cannot revoke them. Production remains unchanged until a separate approval and release.
